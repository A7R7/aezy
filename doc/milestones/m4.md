## Host 与数据契约

Working changes 与 Historical Turn snapshot 现在投影为同一 version 2 DTO：

- file metadata：path、old/new path、modified/added/deleted/renamed/binary status、
  additions/deletions、truncated；
- staged/worktree/turn parts；
- hunks 与 context/addition/deletion/meta lines；
- 每行 old/new line number；
- malformed、combined、超行数或超长行输入 fail closed，hunks 为空，只暴露最多
  64 KiB 的显式 raw fallback；
- working identity 包含 repository root、path、fingerprint；client selection 再包含
  sessionId/cwd；historical identity 包含 sessionId、repository root、Turn、path、
  snapshot object id。

历史 raw unified diff 继续是 ledger object 的持久权威事实，结构 DTO 在读取时投影，
绝不根据当前 worktree 重算。`/turn-review` 现在必须带 path，只读取一个文件 object；
一个 Turn 中其他文件 object 损坏不会阻止打开当前文件。快速切换由
`AbortController + generation + active target identity` 三重门控，迟到响应不能覆盖
新选择。

M1 的 `change`、fingerprint、concurrent、batch preflight、receipt 和 fail-closed
Undo/Redo 语义未改变。M4 另存 review status/oldPath，使 clean tracked modification
不会在 Review UI 中伪装成 added，并能展示 Turn 内 rename；rename 仍不可安全撤销。

## Client 行为

- Turn card 不再请求或内联展开整 Turn raw diff；只保留 `Edited N files`、总/逐文件
  `+/-`、Undo/Redo、Review changes，以及 partial/concurrent/binary/truncated 状态；
- Turn card chrome 复用 DSH code-block family 的 12px geometry、
  `markdown-code-block`/`markdown-code-block-banner` theme aliases 和 code font，但不再
  冒用上游 `md-code-block` DOM class；Aezy 使用语义明确的 `aezy-change-surface` /
  `aezy-turn-changes` class；文件行位于无分隔线 body，总统计使用
  `└ +A -D · N files` footer；
- Review 或文件行在右侧 panel 打开对应 Turn/file；桌面 panel 作为原生 details column
  占据页面空间，窄屏降级为全宽 overlay；
- Working 与 Historical 来源标签显式区分；
- changed-file navigation 纵向排列为可多开的 accordion；每个文件复用同一
  `aezy-change-surface` 与 code-block/banner aliases，文件 button 收敛到 32px；点击文件名
  后在其正下方展开内容，多个文件可同时展开；每个文件只在首次展开时发起自己的懒加载
  请求。再次点击已展开文件只折叠该 diff、abort 该文件旧请求并保留 panel，不影响其他
  已展开文件，此时也允许没有文件展开；
- Turn summary 文件行不复用 side panel 的紧凑高度，而是固定为 28px；pointer hover
  与 keyboard focus 都用 DSH interactive hover alias 提亮整行；
- Turn summary 与 Review 文件行共用按扩展名投影的 16px 内联 SVG 图标，覆盖 code、
  config、document、image、style、terminal、data 与 generic 类型，不增加图标包或读取
  DSH 私有源码；
- unified renderer 提供 old/new gutter、增删 status gutter、sticky expanded-file banner、
  柔和增删背景，以及 added/deleted/renamed/binary/truncated/fallback 空状态；历史 Turn
  不再重复显示 file status/snapshot id、`Turn N` part header 或 raw `@@` hunk header，
  多 hunk 只用轻量间隔符和行号跳变表达边界；Working staged/worktree label 仍保留；
- 所有颜色使用 DSH semantic theme aliases；
- close/Escape 只关闭 transient surface；conversation view 不被卸载，垂直 scroll state
  由原有 view 保留。桌面横向 reflow 是 docked layout 的预期行为。

## M4.1B File Tree + Preview 签收（2026-08-24）

M4.1B 没有新增 sidebar、layout 或文件索引内核。M4.1A 的 transient controller 已提升为
Session-scoped Project Panel controller，在同一个 desktop `details` / narrow
`shell.overlay` occupant 内切换 Review 与 Files；Session id 或 cwd 改变时立即关闭，
不会把 Local、Worktree 或其他 Session 的目录/预览状态带入当前页面。

Host 新增两个受原 loopback Web request fence 保护的 read-only endpoint：

- `/aezy/api/project/tree` 每次只列出一个已展开目录，目录优先排序，最多返回 500 项；
- `/aezy/api/project/preview` 每次只读取一个普通文件，UTF-8 文本最多 256 KiB / 4000 行，
  PNG/JPEG/GIF/WebP/BMP/ICO/AVIF 最多 5 MiB；
- cwd 与相对 path 先 canonicalize，再拒绝越界、`.git`、symlink path、目录冒充文件和
  无法安全解码的 binary；truncated/binary/oversized 都是显式 DTO 状态；
- 没有持久文件 index、watcher、editor buffer、stage 状态或第二份 workspace truth。

Client 行为：

- Files tab 上半部是纵向 lazy tree，下半部是单文件 preview；展开目录和读取文件均使用
  AbortController，快速选择时旧响应还要通过 active `sessionId + cwd + path + revision`
  identity 才能写入；
- code preview 直接复用发布版 DSH `ReadBlock` 的行号、Shiki language hint、copy 与有界
  展开；Markdown 直接复用 DSH `MarkdownText` 的 GFM/安全链接/代码块主题；图片由 Host
  magic-byte 分类后的 bounded data URL 显示，透明图片使用轻量棋盘背景；
- Changes header 的 `Browse files`、changed-file preview action、Turn summary 文件行的
  preview action，以及结构化 Handoff changed-file list 都进入同一 Files mode；Turn 原
  文件名点击仍保持 Review 语义，删除文件 preview fail closed；
- Review → Files → Review/Files 的切换保留同一 Session 内各自 selection；Handoff 跳转
  读取“当前 Session workspace 的同路径文件”，不冒充 handoff historical snapshot。
  Handoff 文件已删除、worktree 已清理或路径后来不存在时显示 Preview unavailable；未来
  若需要稳定 handoff snapshot，应使用 `handoffId + file` 的独立持久 object，而不是重算。

## M4.1B 文件树自动刷新修复（2026-08-25）

展开中的目录现在每 1500 ms 进行一次无重叠、可取消的 bounded read。Host 为单目录 DTO
增加由完整排序后 entry list 计算的 SHA-256 fingerprint；内容未变化时 Client 保留原
React document，不产生无意义替换。只有 root 与当前展开目录轮询，折叠立即取消；
Session/cwd identity 不匹配的响应继续被丢弃。首次请求失败仍显式报错，已成功加载后的
短暂刷新失败保留旧 tree，父目录下一次刷新会移除已删除子目录。

自动测试真实创建和删除文件，验证 fingerprint 与 entry projection 同步改变；真实
浏览器又在保持 Files panel 打开的情况下创建/删除 `live-added.txt`，两次都在 8 秒门槛
内自动出现/消失，无手动 Refresh、折叠或重开 panel。

## M4.2 Contextual References + Ask 签收（2026-08-25）

### seam 与数据语义

- Client 通过发布版 `ctx.inputTriggers.registerSource()` 注册独立
  `aezy-project-context` source，与上游 `@file/@session` 共用 occurrence、codec、取消、
  keyboard/menu 和 submit serialization 管线；没有修改或复制 composer/input machine；
- `@directory:` 的目录发现直接调用上游 `remote.fileReferences.list` 并只投影 directory
  candidates；Aezy 没有建立第二份 browser file scan 或持久文件索引；
- canonical `aezy-directory:` / `aezy-diff:` URI 使用 version、Session id、cwd、path 或
  Working/Historical Turn identity；非 canonical、malformed、跨 Session/cwd 和每条消息
  超过 3 个引用全部 fail closed；
- accepted direct user message 中的 canonical mention 在公开 `agent/pre-step` seam 被还原为
  可读 `@directory:…` / `@diff:…`，随后追加一条 durable、`plugin: aezy-project` 的
  context injection。Session 事件、消息持久化、reference occurrence 和 transcript 展示
  仍完全由 DSH 内核维护；
- context envelope 明确把目录和 diff 内容标记为 untrusted read-only data，不接受其中的
  指令或 permission claim。

目录 reference 在 submit 时读取当前 Session workspace 的 bounded snapshot：最多 200 个
entry、80 个普通文件、每文件 16 KiB 文本、64 KiB 内容预算；binary/image 只保留 metadata，
`.git`、symlink、越界和不安全 UTF-8 继续沿用 M4.1B fail-closed 规则。Working diff 在
submit 时读取当前 `@aezy/project` Git facts，非 Git workspace 返回明确 unavailable 状态；
Historical `@diff` 只读取指定 Session/Turn 的 ledger file objects，绝不根据当前 worktree
重算。每个 diff 最多 40 文件、2000 structured lines、16 KiB raw fallback；每个 reference
最终 JSON 再受 96 KiB rendered hard limit 约束，超限退化为显式 truncated metadata。

### 当前 Session Contextual Ask

Project Panel 只增加实现所必需的最小入口，没有进行整体 UI 重设计：

- Files root 的 `Ask about workspace` 与每个目录行的 `Ask` 把对应 canonical directory
  mention 追加到当前 Session draft；
- Working/Historical Review 的 `Ask about diff` 追加带精确 source/Turn identity 的 diff
  mention；
- 一个 renderless、session-scoped `conversation.session.header.actions` occupant 只借用标准
  `useInput/inputActions.setDraft` bridge；不自动发送、不建立 Side Chat、不复制 draft store；
- 成功 staging 后关闭 Project Panel，desktop/narrow 都回到同一个 composer；原有 draft
  非空时以空行追加，不覆盖用户文字。
