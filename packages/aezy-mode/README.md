# @aezy/mode

Alpha-only external presentation and policy for run methods. It restores DSH's
native preset surfaces, contributes the non-deletable `codex-app-server` preset,
projects shared model identities onto compatible routes, and fences that preset to the
`aezy-codex` provider. It does not implement an Agent, Session, model, tool,
approval, or persistence runtime.

The Host bundle contains only preset metadata and a provider-fence overlay. The
isolated runtime selector appends the overlay to the installed DSH release's
authoritative `standard` composition, then stages the generated preset beside
legacy `aezy`. DSH therefore remains the owner of version-specific tool, plan,
compaction and subagent invariants; Aezy does not copy that composition.

The composer uses the published DSH `Menu` / `Button` primitives, including
theme tokens, a viewport-bounded portal, selected state, Escape/outside-click
dismissal and a refresh footer. It contains no native model/effort `<select>`.
Failed catalog/selection requests remain visible and retryable. `/model` and
the composer use the same union directory. Only explicitly owned GPT and DeepSeek
route aliases are merged; equal display names are not an identity contract.
Changing a blank Session's preset preserves the model identity and supported
effort, selecting its compatible native or Codex transport through DSH's public
model-selection RPC. Missing routes remain visible with a reason, without silent
model/provider fallback. Effort capabilities remain owned by the actual route.

There is still one run-method menu, grouped into DSH work presets and the Codex
execution engine. Only presentation changes: the public slot's injected business
face is reused, and the shipped controller owns staging, blank-session checks,
creator drafts, and durable selection. There is no separate engine selector or
new preset state machine. Started Sessions retain DSH's preset lock, historical
`aezy` Codex Sessions retain their engine, and Codex Thread/runtime channel fences
are unchanged. Model identity does not share authentication or migrate Threads.
